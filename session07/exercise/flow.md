# 実習: リクエスト/レスポンスの流れを書いてみよう

TODO アプリで「新しい TODO を追加する」とき、ブラウザとサーバーの間で
何が起きているのかを順序立てて書いてみましょう。

コードを読むだけではなく、自分の言葉で説明することで
「フロントエンド」「バックエンド」「データベース」の役割分担が見えてきます。

---

## シナリオ

> ユーザーがブラウザ上で「牛乳を買う」と入力して**追加**ボタンを押した。
> 画面のリストに「牛乳を買う」が表示された。
>
> このとき、ブラウザとサーバーの間では何が起きている？

---

## 書き方のヒント

以下の登場人物を使って、「誰が」「何を」「どこへ」するのかを意識して書きましょう。

- **ブラウザ**（HTML / CSS / JavaScript が動く場所）
  - `static/app.js` の関数
  - `fetch()`
- **サーバー**（FastAPI = `main.py` が動く場所）
  - `@app.post("/todos")` のエンドポイント
- **データベース**（`todo.db`）
  - `INSERT INTO todos ...`

---

## あなたが埋める欄

以下の箇条書きを、**10 ステップくらい**で埋めてみましょう。

- ユーザーがブラウザ上で「牛乳を買う」と入力して追加ボタンを押す
- ブラウザ上のJavaScript（`static/app.js`）がクリックを検知し、入力された「牛乳を買う」というテキストを取得する
- `static/app.js` 内の `fetch()` 関数が起動し、サーバーに向けてPOSTリクエストを行う
- サーバー（FastAPI = `main.py`）がリクエストを受け取り、対応する `@app.post("/todos")` のエンドポイントが動き出す
- サーバーが送られてきたリクエストを解析し、データベースへ保存するためのデータを取り出す
- サーバーがデータベース（`todo.db`）に対して、データを登録するための `INSERT INTO todos ...` のSQL文を発行する
- データベース（`todo.db`）が命令を実行し、新しいTODOとして「牛乳を買う」をテーブルに保存する
- 保存が完了したら、サーバーがブラウザに向けて「保存に成功したよ」というデータをレスポンス（JSON形式）として返却する
- ブラウザ側の `fetch()` 関数がサーバーからのレスポンスを受け取り、処理をJavaScriptへ引き継ぐ
- 画面のリストに「牛乳を買う」が表示される
